## 目录结构


## 需求逐条对照

| 需求 | 实现情况 |
|---|---|
| 1. Whisper 调用生成原始 SRT | ✅ 用 **faster-whisper**（同一套权重、同一 API 家族，快 4–5 倍、显存占用低） |
| 2. 字幕处理：剔除无效 / 分割长句 / 消除重叠 / 设置间隙 | ✅ 四项都实现。**未使用 pysrt**：`subtitle_fix.py` 自带解析与编辑实现（理由见下） |
| 3. 调用 SubtitleEdit 命令行微调时间轴 | ✅ `seconv_tools.py` + `normalize_with_seconv()`，默认启用并已通过零退化验证 |
| 4. 强制 UTF-8 + 校验时间戳格式 | ✅ 输出 UTF-8 无 BOM / LF；校验覆盖负值、越界、非单调、格式非法、超出媒体时长 |
| 5. 单独脚本验证 Aboboo 对齐 | ✅ `check_srt.py`（客观校验）、`probe_aboboo.py`（8 变体探针）、`audit_continuous.py`（连续语流）、`acceptance.py`（一键验收） |

### 关于未使用 pysrt 的说明

需求写了 pysrt，但实际实现是自带的轻量解析/编辑。原因：

1. 校正需要在**词级时间戳**上做切分与吸附，pysrt 只有段级 API，帮不上
2. 自带实现零第三方依赖，PyInstaller 打包更省事
3. 核心模块少一层外部依赖，稳定性更可控

功能（剔除/分割长句/消重叠/设间隙）全部由 `subtitle_fix.py` 实现并有测试覆盖。
pysrt 仍在 `requirements.txt` 中（首次开发时的依赖），如团队要求严格对齐
需求措辞，可将其替换进解析层——但需要重跑全部回归。

## 对外接口（第二板块只需关心这两个）

```python
from model.pipeline import process
from model.asr import AsrEngine

# 推荐：批量处理时复用同一个引擎，避免重复加载模型
# GPU 已实测可用（RTX 4060），直接写 device="cuda"；
# 想自动探测可用 model.gpu_env.gpu_available()
engine = AsrEngine(model="small", device="cuda", compute_type="int8_float16",
                   language="en")

result = process(
    video="D:/videos/unit1.mp4",
    out_dir="D:/out",                       # GUI 的"保存文件夹"
    engine=engine,                          # 复用模型（置 None 则临时创建）
    progress_cb=lambda p, msg: bar.setValue(int(p * 100)),   # 0.0~1.0
    cancel_flag=lambda: worker.is_cancelled(),               # 返回 True 则中止
    make_mp4=True,                          # 是否输出 remux 的 MP4
)
print(result.srt_path, result.cue_count, result.summary())
```

> **GPU 加速**：实测 `small` 从 CPU 42s 降到 GPU 7.8s（5.4x）；
> `large-v3` 在 CPU 上不可用（约 6.2 小时），GPU 上 59s。
> 配置方法与三个踩坑见 [GPU加速-配置与实测.md](GPU加速-配置与实测.md)。
> 自检命令：`venv\Scripts\python.exe scripts\doctor.py --deep`

### 回调契约

| 参数 | 类型 | 说明 |
|---|---|---|
| `progress_cb` | `(float, str) -> None` | 进度 0.0~1.0 与阶段描述。**会在工作线程中被调用**，若直接更新 Qt 控件请用信号槽跨线程转发 |
| `cancel_flag` | `() -> bool` | 返回 True 时中止。取消后**已产出的部分文件会被自动清理**（不会留下残缺 SRT） |

### 异常

| 异常 | 触发条件 | 建议处理 |
|---|---|---|
| `PipelineCancelled` | 用户取消 | 静默忽略，清理 UI 状态 |
| `FileNotFoundError` | 输入不存在 | GUI 提示"文件不存在" |
| `RuntimeError` | ffmpeg 失败 / GPU 缺 CUDA 运行库 | 把异常文本直接显示给用户（已含可操作提示） |
| `ImportError` | 未装 faster-whisper | 提示运行环境安装脚本 |

## 校正流水线（顺序不可调换）

```
1. 剔除        空/纯空白/零时长/无有效字符
2. 按静音切分   Whisper 会把多句合并进一段，必须先切开
3. 波形吸附     起止对齐到真实语音边界
4. 约束        不重叠、间隙达标、时长不超上限
5. 行长约束     按词边界换行（不劈开英文单词，保护 Aboboo 取词）
6. seconv 规范化 Subtitle Edit 命令行收尾（间隙/时长/行长/常见错误）+ 结果校验
```

**为什么第 2 步必须在第 3 步之前**：切分会改变段边界，若先吸附再切分，新产生的边界就失去了吸附效果。

### 第 6 步：Subtitle Edit（seconv）集成

对应需求"调用 SubtitleEdit 命令行做时间轴微调"。实现在
[`model/seconv_tools.py`](<model\seconv_tools.py>)，由
`subtitle_fix.normalize_with_seconv()` 在写出 SRT 之后调用。

**定位说明**：seconv 的 `--offset` 只能**整体平移固定毫秒数**，而实测 Whisper
偏差是逐句不一致的（中位 −92ms、标准差 133ms），整体平移无法消除逐句差异。
所以主校正必须靠波形吸附，seconv 承担**字幕工程规范收尾**：

| seconv 选项 | 对应需求措辞 |
|---|---|
| `--apply-min-gap:<ms>` | 设置字幕间隙（默认启用） |
| `--apply-duration-limits` | 时长上下限 |
| `--split-long-lines` / `--merge-short-lines` | 分割长句 |
| `--fix-common-errors` | 常见错误修正（默认关闭，会重排内容） |
| `--balance-lines` / `--beautify-time-codes` | 排版规范化 |

**两个实测坑**：

1. **seconv 默认输出带 BOM**（官方文档：UTF-8 BOM on output）。必须显式加
   `--encoding:utf-8-no-bom`，否则编码规范被破坏。
2. **seconv 强制输出 CRLF**（实测与输入换行无关）。`normalize_with_seconv`
   会在其后统一回 LF，保证交付格式不因"是否启用 seconv"而变。

**安全设计**：规范化后用 `read_srt_cues` 重新解析校验；条数减少、出现重叠、
时间轴逆序任一情况就**回滚**到规范化之前。字幕是核心产物，宁可放弃规范化
也不能交出坏结果。seconv 不可用时静默降级（只记日志），不阻断主流程。

**安全性已验证**（`scripts/verify_seconv_safe.py`）：

| 指标 | 仅吸附 | 吸附+seconv |
|---|---|---|
| 条数 | 100 | 100 |
| 起点命中 | 99 | 99 |
| 终点提前 / 重叠 / 结构错误 | 0 / 0 / 0 | 0 / 0 / 0 |
| 词数 | 439 | 439（零丢失） |
| 起点位移 | — | 中位 0ms，100/100 未改动 |
| BOM / CRLF | 无 / 无 | 无 / 无 |

结论：**未造成任何退化**，可作为默认流程的一环。

## 开发中的真实缺陷记录（已修，勿回退）

这些 bug 的共同特点是**多数不触发任何结构检查**，只表现为音频与文本错位或观感问题：

### 1. 区间空间不一致 → 时间轴乱序与 1600ms 重叠
判断"是否跨多句"用合并后的语音区间（119 条），把词分派到区间却用未合并的（123 条）。
结果整段不切分，起点早于前一条。
→ **修正**：两处必须用**同一个**区间空间，并补 `_group_contiguous` 按词间停顿兜底。

### 2. 重叠时丢弃字幕 → 静默丢字
早期让前一条避让后一条起点，当后一条起点不可信（过度切分碎片）时吃掉了整句话 ——
实测**丢失 40 个词次、丢弃 19 条**。
→ **修正**：优先**合并**而非丢弃；合并后必须 `continue`，否则内容重复
（实测词数从 442 膨胀到 **1185**）。

### 3. 吸附规则一刀切 → 起点越过紧邻锚点
切分段的起点已取首词位置，可能**略晚于**锚点。仍用"下一个语音起点"会越过紧邻锚点
（实测 11.720 被吸到 13.208，该条压成 0 时长、文本错位到下一句读音）。
→ **修正**：引入**规则 1（包含优先）**——起点落在某条语音区间内部就归属那一条。
这条规则同时修掉了下面第 4 条。

### 4. 只知道吸起点、忘记吸终点 → "字幕消失得比声音早"（用户实测反馈）
旧条件只接受"**不晚于**字幕末端"的语音终点，而 Whisper 的段尾系统性偏早，
于是每个更晚的真实终点都被排除：**全片 103/109 条的真实语音终点更晚，88 条早结束 >50ms，最大 337ms**。
→ **修正**：把终点对齐到**起点所归属那条语音区间的结束**（字幕的职责是覆盖整句话）。
另把 `min_duration_ms` 默认改为 **0**：早期为了凑满 800ms 而把终点撑到静音里
（`Project` 从真实的 268.093 拉到 268.200），破坏了"对波形忠实"这一原则。

### 5. 吸附锚点未滤噪声碎片 → 24ms 伪区间劫持字幕
波形上存在 **24ms 的伪语音区间**（268.409–268.433，实为噪声），
它被当成合法锚点，把 `Project` 的终点从正确的 268.093 拉到 268.433。
→ **修正**：新增 `min_anchor_speech=0.30`，锚点用比切分更严的阈值
（切分用 `min_speech=0.10`，锚点是"字幕起止的基准"，必须更干净）。

### 6. 静音阈值硬编码 → 连续语流下质量下降（审计发现）
`min_silence` 原先硬编码 0.25s。跟读素材句间停顿 2.7s 时正常；但连续语流停顿
仅 0.34s，阈值逼近停顿，**语音段被过度合并（111 段塌成 91 段）**，
起点命中率从 99% 掉到 94%，并出现 3 条终点未覆盖、1 条文本/语音不匹配。
→ **修正**：`extract_boundaries` 默认改为**从信号自适应**推导阈值
（`adapt_min_silence`：探测静音 → 取 [0.12, 3.0]s 区间的 **20% 分位** × 0.42，
夹到 [0.12, 0.30]）。
> 为什么用 20% 分位而不是中位数：实测静音时长是**双峰**的（词内换气 ~370ms、
> 句间停顿 2.7s），中位数落在两峰间的空档（802ms），推出的阈值 337ms 过大，
> 反而把 130 段并成 118 段。低分位落在第一峰左肩，能同时适配两类素材。

修正后连续语流：终点未覆盖 **0**、文本/语音不匹配 **0**、起点命中 **95%**。

## 尚未验证 / 已知限制（诚实清单）

| 项 | 状态 | 影响 |
|---|---|---|
| **Aboboo 是否容忍 BOM** | 未实测（`test_B_utf8bom.srt` 未被导入验证） | 低。输出本就是无 BOM，规避了风险 |
| **Aboboo 是否合并零间隙字幕** | 未实测 | 低。输出间隙 ≥24ms |
| **无词级时间戳的兜底分支** | 从未触发（`_split_text_proportional`） | 中。仅在使用不支持词级时间戳的引擎时才会走到，逻辑未经验证 |
| **非英语内容** | 未验证（仅测过英语） | 中。中文断句/行长规则不同，需另测 |
| **`min_anchor_speech=0.30` 阈值** | 基于本素材标定 | 中。素材语音段更短时可能过度过滤锚点 |
| **GPU 加速不可用** | `cublas64_12.dll` 缺失 | 中。small 模型 CPU 约 30~45s/313s 音频，可接受；large-v3 需 ~815s |
| **`merge_gap` 配置项** | 已不再被切分使用（改用同一区间空间） | 低。属遗留字段，可清理 |

> 测试脚本的副作用（需注意）：`scripts/test_scheduler.py` 开头会
> `shutil.rmtree(test_output/scheduler)`，而它的 `--real` 用例输出就在该目录下，
> 所以跑完调度测试后那份产出会被清掉。第四板块的产出放在
> `test_output/pipeline/`，不受影响。
